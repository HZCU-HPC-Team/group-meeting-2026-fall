程序跑不通排查清单

跑不通时的固定动线：先看现场，再按顺序问五个问题 · 打印友好

0 · 铁律：先看现场，不重跑

报错的第一反应不是「再试一次」，是打开文件对报错行号：cat -n 文件名。同样的错跑第二遍不会变对。第一报错是真的，后面多是雪崩——只看第一条。

1 · 五问排查动线

顺序问题工具
①命令找到了吗？which 命令；自己的程序要 ./（PATH 不含当前目录）
②权限够吗？ls -l 看执行位 x；chmod +x 补
③编译真过了吗？看第一条 error；warning 不挡编译
④链接符号全了吗？undefined reference = 链接期缺实现
⑤退出码说了什么？echo $?：0 成功 · 126 找到但不可执行 · 127 命令没找到

2 · 缺依赖的三阶段（背这张表）

缺在哪一刻缺什么典型报错Linux 补法
编译期头文件 .hfatal error: 'xxx.h' file not foundsudo apt install xxx-dev
链接期函数实现（.a/.so 开发包）undefined reference to 'xxx'装 -dev 包，链接加 -lxxx
运行期动态库本体error while loading shared librariessudo apt install xxx（运行时包）

查「某个文件属于哪个包」：dpkg -S /路径/libc.so.6；看包状态：apt-cache policy 包名。动线：ldd 找到缺的库名 → dpkg -S/apt search 查包名 → sudo apt install。

4 · 版本决定行为

「教科书说要炸但没炸」先查版本，不是玄学。实例：glibc 2.35（Ubuntu 22.04）把数学函数并入 libc，-lm 成了历史遗留；glibc 2.34 起 pthread/dl/rt 同样并入。经典报错可能因系统太新而不复现。

5 · 编译四阶段（复习）

hello.c ─预处理(-E)─▶ hello.i ─编译(-S)─▶ hello.s ─汇编(-c)─▶ hello.o ─链接──▶ hello
        头文件展开            变汇编           机器码碎片        和库拼成整体

file 三种指纹：executable（能跑）/ object（碎片，跑不了）/ text（人读的）。736 字节的 .o 变 33KB 的可执行，差的都来自库里。
