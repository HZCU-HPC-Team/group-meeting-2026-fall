## 一、这次作业到底要什么（五条目标逐条翻译）

### 1. Agent —— 知道它是什么

**人话**：Agent = 模型（大脑）+ Harness（手脚）。
- **模型**就是会思考的 AI（比如我背后的大模型），但它天生只会「输出文字」。
- **Harness**（直译「马具」，可以理解为「身体」）是围绕模型搭的一套程序，让模型能动手：拆解步骤、调用工具（读写文件、跑命令、上网查资料）、看结果、再决定下一步。
- **你的例子**：WorkBuddy 里的「淇毅果」就是一个 Agent——你说「装个 skill」，我自己拆成「找资料 → 建目录 → 给命令 → 验证」几步，还会用工具执行命令、读你截图。

### 2. Skill —— 是什么、怎么装、怎么用

**人话**：Skill = 给 Agent 的一本「专题说明书」，本质就是**一个文件夹 + 一个 SKILL.md**。
- 你敲 `/teach` 时，Agent 读完说明书，就知道该按教学的方法论来干活（先定目标、再上课、再验收）。
- **怎么装**：没有安装程序。把文件夹放进指定目录（`~/.workbuddy/skills/`），重启会话，Agent 启动时扫一遍就登记了。**装 = 拷文件。**
- **你的例子**：teach skill。你 `git clone` 下载了 mattpocock 写好的说明书，拷进去，重启，`/teach` 生效。

### 3. Linux —— 跑通一个程序要做哪些事

**人话**：写好代码 ≠ 能运行。中间隔着五件事，你今天全做过：

| 事 | 人话 | 你的例子 |
|---|---|---|
| 装依赖 | 程序用到别人写好的现成零件，缺了要先装 | 服务器上 gcc、make 都预装了；缺库时用 `apt install` 补 |
| 路径与权限 | 系统要找得到你的程序，且允许你运行它 | `./hello`（路径）、`chmod +x`（权限） |
| 编译 | 把人写的 C 代码翻译成机器能执行的 0/1 文件 | `gcc` 四个阶段 |
| 运行 | 真正启动程序 | `./hello` 输出 hello |
| 排错 | 哪一步坏了就查哪一步 | 四次翻车全修好了 |

### 4. 建库 —— 在自己 GitHub 上新建仓库传代码

**人话**：GitHub 是「存代码的网盘 + 时间机器」。**仓库（repository / repo）**= 一个项目文件夹，git 会记录里面每个版本。
- **你的例子**：`Judy7-coder/c_wedding`——上周用 AI 做的 C 语言新婚动画程序，已经传上去了。这就是作业要求「准备一个自己的东西 + 建库上传」。

### 5. 做贡献 —— 向别人的仓库提 PR

**人话**：想往**别人的**仓库加东西，不能直接改（没权限/不礼貌），规矩是：
1. **clone**：把仓库下载到你电脑
2. **分支（branch）**：在下载的副本里开一条「平行工作线」，随便改，不影响主线
3. **commit**：把改动存档（拍快照）
4. **push**：把快照传回 GitHub 上的分支
5. **Pull Request（PR）**：向仓库主人申请「把我这条线的改动合并进主线」，主人能看到每一行改动，同意（merge）才算完成

**你的例子**：向团队仓库 `HZCU-HPC-Team/group-meeting-2026-fall` 提交 PR #5，放进 `W02/lgj/week2-notes.md` 周报。（因为老师给成员开了写权限，你不用 fork，直接开分支就行。）

## 二、名词小词典（汇报时被问到就照这个说）

| 术语 | 人话 |
|---|---|
| **终端 / 命令行** | 用打字代替点击来操作电脑的窗口。你打的每行叫「命令」，回车就执行 |
| **目录 / 路径** | 文件夹；路径 = 文件的住址，如 `~/WorkBuddy` 里 `~` 代表你家目录 |
| **SSH** | 加密的远程登录协议——「在 A 电脑上打字，操作 B 电脑」。你连实验室服务器用的就是它 |
| **编译器** | 翻译官，把 C 代码翻译成机器码。Mac 上叫 clang，Linux 上叫 gcc |
| **编译四阶段** | 预处理（拼头文件）→ 编译（变汇编）→ 汇编（变机器码碎片 .o）→ 链接（把碎片和库拼成完整程序） |
| **依赖** | 你程序用到但不是你写的零件（如 printf 的实现），缺了程序就跑不起来 |
| **动态库** | 「用的时候才加载」的共享零件包。Linux 上叫 .so，Mac 上叫 .dylib |
| **PATH** | 系统找命令的「搜索清单」。所以运行自己的程序要写 `./程序名`，告诉系统「就在当前文件夹」 |
| **权限** | Linux 每个文件有一排开关（可读 r / 可写 w / 可执行 x），`chmod` 是拨开关的命令 |
| **退出码** | 每条命令跑完留个分数：0 = 成功，非 0 = 失败。126 = 程序在但没权限跑，127 = 程序没找到 |
| **git** | 记录文件每次修改的「时间机器」，装在你电脑上 |
| **GitHub** | 放 git 仓库的网站，多人协作靠它 |
| **clone** | 把 GitHub 上的仓库整个下载到本地 |
| **分支 branch** | 平行工作线。在分支上改不影响主线，改好了再申请合并 |
| **commit** | 存档点（快照），带一句说明文字 |
| **push** | 把本地的存档上传到 GitHub |
| **PR（Pull Request）** | 「请求合并」申请书：我改好了，请审查我的改动，同意就合并 |
| **fork** | 在 GitHub 网页上把别人的仓库复制一份到自己账号（没有写权限时的玩法） |
| **Mach-O / ELF** | Mac 和 Linux 各自的「可执行文件格式」，相当于两种不同的装箱标准 |
| **glibc** | Linux 的 C 语言标准库（printf 等基础功能的家），Mac 上对应物叫 libSystem |

## 三、你敲过的命令逐条翻译（按时间线）

### 第一幕：Mac 上学编译

| 命令 | 人话 |
|---|---|
| `mkdir -p ~/WorkBuddy/teach-linux/playground` | 建一个练习文件夹（`-p` = 中间路径缺了就顺手补上） |
| `cd 某路径` | 「移动到」某个文件夹（change directory） |
| `cat > hello.c <<'EOF' ... EOF` | 把两行 EOF 之间的文字存成 hello.c 文件（一种快速输入文字的方法） |
| `clang -E hello.c -o hello.i` | 只做第一步「预处理」，结果存进 hello.i |
| `clang -S hello.i -o hello.s` | 第二步「编译」，变成汇编代码 |
| `clang -c hello.s -o hello.o` | 第三步「汇编」，变成机器码碎片 |
| `clang hello.o -o hello` | 第四步「链接」，拼成完整可执行程序 |
| `./hello` | 运行当前文件夹下的 hello（`./` = 「此处的」） |
| `file hello` | 问系统：这文件到底是个啥？ |
| `ls -l hello` | 列出文件详情，开头那串 rwx 就是权限 |
| `chmod -x hello` / `chmod +x hello` | 撤掉/加回「可执行」开关 |
| `echo $?` | 问上一条命令「考了几分」（0 成功） |
| `otool -L hello` | 列出这个程序依赖哪些库（Mac 命令） |

### 第二幕：连服务器（真 Linux）

| 命令 | 人话 |
|---|---|
| `ssh lab` | 用加密通道登录实验室服务器（lab 是你提前配好的别名，等于通讯录昵称） |
| 同样一套 gcc 命令 | 在 Ubuntu 上重跑流水线，发现产物变成 ELF 格式 |
| `ldd ./hello` | 列出程序依赖哪些库（Linux 版的 otool -L） |
| `dpkg -S 文件路径` | 反查「这个文件是哪个软件包装的」 |
| `apt-cache policy 包名` | 查某个软件包装没装、什么版本 |

### 第三幕：GitHub 提 PR

| 命令 | 人话 |
|---|---|
| `git clone git@github.com:HZCU-HPC-Team/group-meeting-2026-fall.git` | 把团队仓库下载到本地 |
| `git checkout -b W02-lgj` | 开一条叫 W02-lgj 的新分支并跳上去 |
| `cp 草稿 W02/lgj/week2-notes.md` | 把报告复制进自己名下的目录 |
| `git add W02/lgj/week2-notes.md` | 把这个文件放进「下次存档清单」 |
| `git commit -m "说明"` | 正式存档，附说明 |
| `git push -u origin W02-lgj` | 把存档上传到 GitHub 的同名分支 |
| `git fetch --prune` | 同步远程信息，顺手清掉已失效的分支路标 |
| （网页上）Create pull request | 发起合并申请 |

## 四、期间遇到的问题（汇报时当「踩坑与成长」讲）

| 问题 | 原因 | 学到什么 |
|---|---|---|
| ① 手滑打成 plaground | 打字误差；`&&` 只管上一条成功，不核对路径 | 报错信息里的路径就是线索，逐字符核对 |
| ② heredoc 把 shell 命令存进了 C 文件 | 粘贴不完整，编译器拿到的文件开头混了命令行 | **先 `cat -n` 看现场再修**；gcc 只懂 C 不懂 shell，第一条报错是真的，后面是连锁雪崩 |
| ③ AI 说写好了配置文件，实际没写 | AI 也会犯错 | **报错即真相**：cp 说文件不存在，就是真不存在，别怀疑报错 |
| ④ 把网址粘进终端 | 终端和浏览器是两个入口，zsh 把 URL 当路径执行了 | 终端执行命令，浏览器开网页 |
| ⑤ PR 手快自己合并了 | 绿按钮太顺手 | 对外动作慢点按；git 历史不可抹（补救=新增反向记录），补救前先比成本 |

> 汇报金句：这周最大的收获不是跑通了程序，而是学会了「**遇到报错先看现场，不盲目重跑**」——报错信息是系统在如实汇报案情。

## 五、执行任务你应该获得什么（这就是「学会了」的标准）

1. **一个心智模型**：代码 → 编译（四阶段）→ 可执行文件 → 系统加载（找路径、查权限、装依赖的库）→ 运行 → 退出码。以后跑不起来，按这条链逐环排查。
2. **一张排查清单**：命令找不到？看 PATH 和 `./`。Permission denied？看执行位。undefined reference？链接期缺实现。loading shared libraries？运行期缺库。（参考卡已存在 `reference/0001`）
3. **两个世界的地图**：Mac 和 Linux 是亲戚（命令 95% 相通），但产物格式（Mach-O/ELF）、C 库（libSystem/glibc）不同——写 C 的人心里要有这张对照表。
4. **一套协作礼仪**：clone → 分支 → commit → push → PR，这是全世界的程序员改别人代码的标准动作，你这周真实走过一遍。
5. **一个 AI 使用姿势**：AI 拆步骤、给命令、讲机制；**执行和验证是我的**——报错要自己看、AI 说的话要用命令核实（今天就抓到它一次没写文件就说写好了）。
