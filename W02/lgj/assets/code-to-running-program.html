teach-linux · Lesson 0001

一份代码是怎么变成「跑着的程序」的

使命：在 Linux 上独立跑通程序，终结「代码没错却跑不起来」· 存档版，学习以对话实操为准

0 · 这节课解决什么

「代码没错却跑不起来」卡住的从来不是 C 语言，而是代码之外那层：编译、链接、权限、路径、运行时。这节课把整条流水线亲手走一遍，每一步都看见中间产物。

1 · 流水线全景

hello.c ──预处理──▶ hello.i ──编译──▶ hello.s ──汇编──▶ hello.o ──链接──▶ hello(可执行)
          头文件展开          变汇编指令        机器码碎片        和库拼成整件
          宏替换              (人类可读)       (还不完整)        (能跑了)

平时敲 clang hello.c -o hello 是四步连着做。看不见步骤 = 出错时不知道坏在哪一环。

2 · 实操命令（按顺序敲）

mkdir -p ~/WorkBuddy/teach-linux/playground && cd ~/WorkBuddy/teach-linux/playground
cat > hello.c <<'EOF'
#include <stdio.h>
int main(void) {
    printf("hello\n");
    return 0;
}
EOF
clang -E hello.c -o hello.i   # 预处理：头文件被展开成几百行
clang -S hello.i -o hello.s   # 编译：变成汇编，可以打开看
clang -c hello.s -o hello.o   # 汇编：变成机器码，但还跑不了
clang hello.o -o hello        # 链接：补上 printf 的真身
./hello
file hello hello.o hello.s && ls -l hello

3 · 两个经典「跑不起来」的机制

坑一：只敲 hello 不敲 ./hello

Shell 找命令只搜 PATH 环境变量里列的目录，当前目录 . 出于安全从来不在里面。所以必须 ./hello 明说「当前目录下这个」。echo $PATH 可亲眼看搜索清单。

坑二：Permission denied

chmod -x hello && ./hello    # 故意撤掉执行位 → Permission denied
chmod +x hello && ./hello    # 加回来 → 正常跑

ls -l 开头的 -rwxr-xr-x 里，x 就是执行位。内核加载程序前检查它，没有就直接拒——这不是玄学，是内核的一行检查。

退出码

echo $?   # 看上一条命令的退出状态：0 = 成功，非 0 = 失败

这是 &&、||、脚本判断、CI 报绿的底层依据。

4 · Mac 与 Linux 的差异速记

点MacLinux
编译器clang（gcc 是它的别名）真 gcc / 也可装 clang
内核XNU（BSD 系）Linux
底层库libSystemglibc
流水线四阶段完全一致，命令 95% 相通

5 · 排错顺序（背下来）

跑不起来时按此问自己：① 命令找到了吗（which / 是否要 ./）→ ② 权限够吗（ls -l 看 x 位）→ ③ 编译真过了吗（有没有 error，warning 不挡编译）→ ④ 链接符号全了吗（undefined reference = 链接器没找到函数真身）→ ⑤ 退出码说了什么（echo $?）。

有不懂，直接问淇毅果（你的教学 Agent）——追问永远免费。
