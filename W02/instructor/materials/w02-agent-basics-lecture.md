## 一、从"会说话"到"会干活"

- 聊天机器人：给文字、回文字——只能"动嘴"；
- Agent：给目标，它自己拆步骤、动手（读写文件、敲命令、开浏览器、调 API）、看结果、继续干——能"动手"；
- 差别不在模型"更聪明"，在于模型外面套的那层东西：**Harness**。

---

## 二、Agent = 模型（大脑）+ Harness（手脚）

```
Agent = 模型（大脑） + Harness（手脚 + 循环 + 上下文/权限）
```

循环图：

```
            目标（你想让它干的事）
                    │
                    ▼
          ┌──────────────────┐
          │  模型（大脑）     │  理解目标、拆步骤、决定下一步
          └────────┬─────────┘
                   │ ① 生成“调用哪个工具、传什么参数”
                   ▼
          ┌──────────────────┐
          │  Harness（手脚）  │  真正执行：文件、终端、浏览器、API
          └────────┬─────────┘
                   │ ② 把执行结果（观察）喂回去
                   ▼
              回到模型，继续下一轮 → … → 产出
```

- **模型（大脑）**：理解目标、拆步骤、决定下一步干什么；
- **Harness（手脚）**：真正执行动作，管理上下文、权限、日志；
- **循环**：观察 → 决策 → 行动 → 观察……直到完成——"自主"就是这么来的；
- **为什么"有手有脚"**：模型只会输出指令（"运行 `ls`"），Harness 去执行，再把结果回灌给模型；
- 一句话：**模型负责想，Harness 负责做**。换模型（Kimi / DeepSeek）只是换大脑，手脚不变；
- （可选）MCP 可以理解成"给 Agent 接工具的标准插口"。

## 三、市面上常见的 Agent 形态

| 形态 | 例子 | 特点 |
|---|---|---|
| IDE 集成 | Qoder、Cursor、Copilot Agent | 贴身改代码、跑终端，开发场景最顺 |
| 终端 CLI | Claude Code、Codex CLI | 直接在仓库 / 服务器里操作，最接近工程自动化 |
| 桌面 / 办公 | WorkBuddy 等 | 处理本机任务、文档与日常操作 |
| 网页 / 云端 | ChatGPT Agent、Manus 类 | 浏览器操作、云端跑长任务 |
| 技能 / 插件 | Claude Code Skills、Qoder Skills | 不是独立 Agent，是给 Agent 装的"技能包" |

今天现场看两种：**Qoder（IDE 集成）** 和 **Claude Code（插件 / 终端）**。

---

## 四、Skill：给 Agent 装"技能包"

- **定义**：把"某类任务怎么做"打包成可复用包——说明 + 步骤 + 脚本 / 模板 + 检查清单，Agent 需要时加载；
- **类比**：给新同事的 SOP 手册；或游戏里的"技能书"；
- **为什么需要**：模型很通用，但不懂我们内部的规矩（仓库结构、笔记格式、服务器流程）；Skill 把团队经验固化，结果更稳、不用每次重复解释；
- **例子**：
  - `写探索笔记`：按固定格式生成 Markdown；
  - `部署到服务器`：检查环境 → 构建 → 重启 → 验证；
  - `周报`：按模板汇总本周进展；
- **现成的高人气仓库（推荐）**：[`mattpocock/skills`](https://github.com/mattpocock/skills)——作者是知名前端教育者 Matt Pocock，其中有一个专教人学习的 [`/teach` skill](https://www.aihero.dev/skills-teach)：
  - 把当前目录变成"教室"，分多节课、一节建立在上一节之上；
  - 不靠模型瞎编，引用它找到的高可信资料，并记录你的学习状态；
  - 给它一个主题，它就能带你把基础概念和使用细则走一遍；
  - 例：用它学"在 Linux 上跑通一个程序需要做哪些事"；
- 另一个值得看的：[`obra/superpowers`](https://github.com/obra/superpowers)——把一整套开发方法论拆成可组合的 skill，比如 `brainstorming`（先问清意图）、`test-driven-development`（先写测试再实现）；
- **形态**：Claude Code 的 skill 是一个文件夹（`SKILL.md` + 资源）；Qoder 类似；slash command 是轻量版；
- **边界**：Skill 不改变模型本身，只是给"大脑"提供更专业的做事方法。

---

## 五、小结

- **很多 Agent 产品本质上只是一个 Harness**：接入不同模型的 API，就换了它的大脑；
- 会用 Agent = 会描述目标 + 会给工具权限 + 会检查结果 + 会把经验沉淀成 Skill；
- 它"有手有脚"也意味着有风险：**先看再跑、权限边界、结果留档**（接回第一课的规矩）；
- **环境建议**：跟开发、程序有关的场景，Agent 的工作环境尽量选在**服务器上**，或者自己电脑的**虚拟机**里——更干净、更高效，也不怕折腾坏本机。

## 七、布置作业

**规则不变**：先问 AI → 动手去做 → 做成后把收获留档。W01 探索笔记没交的同学，这次可以跟着再学，不急。

**作业目标**（具体操作可以交给 AI 来做，但整个流程自己要懂）：

1. **Agent**：知道它是什么——模型 + Harness，能自己拆步骤、调用工具、看结果；
2. **Skill**：知道它是什么、怎么装、怎么用，并亲手试用一个（`teach`）；
3. **Linux**：知道在服务器上跑通一个程序要做哪些事——装依赖、路径与权限、编译 / 解释执行、运行、排错；
4. **建库**：知道怎么在自己的 GitHub 上新建仓库并上传代码；
5. **做贡献**：知道怎么向别人的仓库提 PR（fork / 分支 / Pull Request），完整走通一次。

### 作业：AI + GitHub 闭环

1. 准备一个"自己的东西"——可以用 AI 做一个新的小东西（小网页 / 小游戏 / 命令行小工具 / 自动化脚本），也可以是自己以前的作业、项目、作品；题材不限；
2. 在个人 GitHub 新建一个仓库，把它传上去（让 AI 手把手教，网页版或本地 git 均可）；
3. 给自己的 Agent 装上 [`mattpocock/skills`](https://github.com/mattpocock/skills) 里的 `teach` skill，用它学一个 Linux 基础主题——建议就学「**在 Linux 上跑通一个程序需要做哪些事**」（装依赖、编译 / 解释执行、权限、路径、运行、排错）；
4. 向团队仓库提 PR：在 `W02/<你的缩写>/` 放一份说明文件（名字随意，按仓库规则用英文即可）——写清两件事：**这周做了什么**（东西是什么、仓库链接、AI 帮了什么忙）和**学到了什么**（用 `teach` 学到的要点、自己的体会，以及以后怎么维护更新自己的 GitHub 账号、怎么给别人的仓库做贡献）。



**成本提示**：想体验 API 路线的，可以先在 DeepSeek 少充一点感受一下；不充值也不影响完成作业（网页版 / Qoder / WorkBuddy 都可以）。

### 提交方式

- 截止：下次组会前；
- PR 提交到团队仓库的 `W02/<你的缩写>/`。

## 收尾

记住三件事：Agent = 模型 + Harness；Skill 是"技能包"；会用 Agent 的关键是描述目标 + 检查结果 + 留档。课后把作业走通。
