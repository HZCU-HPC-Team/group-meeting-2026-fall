## 本周要做什么

### 新生

**规则不变**：先问 AI → 动手去做 → 做成后把收获留档。

**本次主题**：优化 pivot——版本管理、出火焰图、减少计算量。

**本周作业：**

- [ ] **1. 版本管理**
  - 在 baseline 上打标签：`git tag v0-baseline`；
  - 以后每改一版就是一个 commit；
  - 建一个 `iteration.md`（就是一张表），每版记一行：改了什么、花了多少时间、对应哪个 commit。

    | 版本 | commit | 改了什么 | 耗时（中位数） | 相对上一版 | diff |
    |---|---|---|---|---|---|
    | v0-baseline | `<commit>` | 原始代码 | | — | ok |
    | v1 | `<commit>` | | | | ok |

- [ ] **2. 出一张火焰图**
  - 用 perf：`perf record -g ./pivot_O0 <输入文件>`，再用 FlameGraph 脚本生成 `flame.svg`；
  - 或者用本地已装的 VTune：激活环境后做 hotspots 分析，GUI 截图或 `-report` 输出；
  - 图上写清输入规模、采集命令、坐标轴和单位——比赛报告要用。

- [ ] **3. 把热点抽象成式子**
  - 算清楚：多少组枢轴、每组多少个点对、哪些计算在重复；
  - 写成 `T ≈ C(n,k) × n² × 常数`，标出重复的部分。

- [ ] **4. 让 AI 提减少计算量的想法**
  - 把热点代码和 perf / VTune 的结果发给 AI，让它提几个方案；
  - 追问：减少的是哪一项计算、为什么、要改哪里、有没有正确性风险；
  - 追问后还是理解不了 → 不必强求；能理解、试了确实有用 → 最好，可以多试几个。

- [ ] **5. 测一遍并记录**
  - 选一个能理解的想法实现，只改一处，改完保证 `diff` 一致；
  - 重新编译，至少跑 3 次取中位数；
  - 把这一版加进 `iteration.md`：版本、commit、改了什么、耗时、相对上一版、`diff` 结果；
  - 没变快也要记，失败就 `git revert` 回去。

- [ ] **6. 下次组会分享（3 分钟）**
  - 火焰图 + 式子 + 你试的想法 + 优化前后的时间对比。

**提交**：截止下次组会前，PR 到 `W04/<你的缩写>/`。
