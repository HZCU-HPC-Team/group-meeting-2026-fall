## 一、本次讲了什么

### 主题

第四课——优化 pivot：版本管理、可视化、减少计算量

### 要点

1. **版本管理**：baseline 打 tag，一次改动一个 commit，失败用 `revert`；每版都能说清耗时和源码。
2. **profiling 出图**：用 perf 就交火焰图；本地已装 VTune，激活环境后可以试；工具不限，图必须有。
3. **先抽象再动手**：把热点写成式子（多少组枢轴、多少点对、哪些重复），再想减少计算量的办法。
4. **AI 可以问**：让它列候选方向，结论由测量决定。
5. **记录清楚**：每一版花了多少时间、源代码是哪个 commit，缺一项就算没记录。

### 结论与共识

- 流程固定为：profiling → 可视化 → 抽象 → 提 idea → 改一处 → 测量 → 记录。
- 删日志属于省 I/O，不算减少计算量，记录时要标注清楚。

### 新生

**规则不变**：先问 AI → 动手去做 → 做成后把收获留档。

**本周作业：版本记录 + 一张性能图 + 一段抽象与 idea**

- [ ] **第 0 步：准备**
  - 确认 baseline 能编译、能跑、`diff` 一致；
  - 在 baseline 上打标签：`git tag v0-baseline`；
  - 新建 `iterations.md`，先把 baseline 这一行填上（耗时、编译选项、diff）。

- [ ] **第 1 步：采集数据并出图**
  - **路线 A（默认，perf 火焰图）**：
    ```bash
    perf record -g ./pivot_O0 uniformvector-2dim-5h.txt
    perf script | ./FlameGraph/stackcollapse-perf.pl | ./FlameGraph/flamegraph.pl > flame.svg
    ```
    - 栈缺失就加 `--call-graph dwarf` 重采；
    - 没有 FlameGraph 脚本，从 `brendangregg/FlameGraph` 拉一份；缺 `perl` 找讲师。
  - **路线 B（VTune，本地已安装）**：
    ```bash
    source /opt/intel/oneapi/setvars.sh   # 以机器上实际路径为准
    vtune --version
    vtune -collect hotspots -result-dir vtune-r1 -- ./pivot_O0 uniformvector-2dim-5h.txt
    vtune -report summary -result-dir vtune-r1
    ```
    - 有图形界面就 `vtune-gui` 打开结果，截图上传；
    - 没有图形界面就用 `-report` 输出。
  - **图的要求**：标题、坐标轴与单位、输入规模、采集命令齐全，能直接放进比赛报告。

- [ ] **第 2 步：把热点抽象成式子**
  - 数：多少组枢轴（C(n,k)）、每组多少点、多少点对、每对算几次；
  - 写：`T ≈ C(n,k) × n² × 每对点的常数`；
  - 标出哪些计算是重复的、重复了几次。

- [ ] **第 3 步：提 idea 并改一处**
  - 写 2–3 个候选，每个写清：改哪里、减少哪一项、预期效果；
  - 问 AI 可以，但自己选一个；
  - 只改一处，保持 diff 小到能逐行读懂。

- [ ] **第 4 步：测量与记录**
  - 重新编译 → `diff` → 至少 3 次取中位数；
  - 更新 `iterations.md`：版本、commit、改了什么、编译选项、耗时、相对上一版、diff、结论；
  - commit 信息带数据：`opt: <改动> | <选项> | 132.4s -> 41.7s | diff ok`；
  - 没有变快也要记录，失败用 `git revert` 回退。

- [ ] **第 5 步：分享准备（3 分钟）**
  - 火焰图 / VTune 图 + 式子 + idea + 优化前后的时间对比。
