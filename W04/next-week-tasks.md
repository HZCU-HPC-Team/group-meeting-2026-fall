## 一、本次讲了什么

### 主题

第四课——从 perf 到优化：把数据变成图，把改动变成记录

### 要点

1. **perf 是证据，不是作业**：先有数据，才谈优化；没有热点数据就改代码等于蒙眼。
2. **三张图**：热点条形图（时间花在谁身上）、火焰图（谁调用了它，选做）、前后对比图（这次改动值不值）。
3. **先写假设再动手**：因为 A，所以改 B，预期 C。AI 只做参谋，一次只改一处。
4. **每轮都验证**：重新编译 → `diff` → 至少 3 次取中位数 → 算加速比。
5. **可追溯**：baseline 打 tag，一次改动一个 commit，失败用 `revert`，每一轮都填迭代表。

### 结论与共识

- 优化流程固定为：看数据 → 写假设 → 改一处 → 测量 → 记录。
- 每次改动都有版本、有数据、能回退；失败的尝试也要留档。
- 编译选项只作对照；算法级优化与并行化放在 W05。

**规则不变**：先问 AI → 动手去做 → 做成后把收获留档。

**本周作业：一张热点图 + 至少两轮迭代 + 一份可复现的记录**

- [ ] **1. 补齐并可视化 perf 数据**
  - 热点条形图人人要做：横轴耗时占比、纵轴函数，数据来自 `perf report --stdio`；
  - 有调用栈的加做火焰图（`perf record -g`）；
  - 图上标采样总数、采集命令、机器；拿不到调用栈就说明原因。

- [ ] **2. 至少两轮优化迭代**
  - 每轮先写下假设："因为 perf 显示 `X` 占 `Y%`，所以我猜瓶颈是 `…`，打算改 `…`"；
  - 一次只改一处；可以让 AI 解释热点、列候选改法，但不要让它重写整个文件；
  - 每轮都要重新编译、`diff`、至少测 3 次取中位数；
  - 至少一轮有明确收益；另一轮允许失败，但必须记录并 `revert`；
  - `diff` 不一致的改动不能保留。

- [ ] **3. 迭代表 + 前后对比图**
  - 维护 `iterations.md`，列：版本、commit、改动、编译选项、次数、中位数耗时、相对上一版、相对 baseline、diff、结论（保留 / 回退）；
  - 基线打标签：`git tag v0-baseline`；一次改动一个 commit，message 带数据；
  - 用表里的数据画前后对比图：横轴版本、纵轴耗时；
  - 输入数据、`result.txt`、`run.log` 不进仓库。

- [ ] **4. 分享准备（3 分钟）**
  - 讲一张热点图 + 一张对比图 + 一句假设 + 一个结论；
  - 例如："热点在 `X`，我猜是 `Y`，改了 `Z`，从 `a` 秒到 `b` 秒，`diff` 一致"。

- [ ] **5. 预习（轻量，不改代码）**
  - 打开 `pivot.c` 里的 `SumDistance`，用自己的话写出：它有几层循环、每层在做什么、哪些计算在重复。这是 W05 的起点。
