## 四、讲了什么

### 本次流程顺序

- [x] 学生先汇报
- [x] 讲师先介绍内容

### 议题

1. 版本管理：baseline 标签、一次改动一个 commit、失败 `revert`、迭代表
2. profiling 与可视化：perf 或其他工具，必须出热点图
3. 把热点抽象成式子，自己提减少计算量的 idea，AI 辅助
4. 现场演示一轮完整流程
5. W04 作业布置

### 讨论要点

#### 议题一

- 每一版必须能回答：花了多少时间、源代码是哪个 commit。
- 提交信息带耗时变化；失败也留档，用 `revert` 回退。
- 迭代表：版本、commit、改动、编译选项、耗时、加速比、diff、结论。

#### 议题二

- 默认路线：`perf record -g` 采集，用 FlameGraph 脚本出火焰图。
- 备选路线：本地已安装 VTune，激活环境（`source /opt/intel/oneapi/setvars.sh`）后可做 hotspots 分析，GUI 截图或 `-report` 输出。
- 必须交图，图上标坐标轴、单位、输入规模、采集命令；比赛报告需要图片。

#### 议题三

- 先抽象：多少组枢轴、每组多少点对、哪些计算重复，写成 `T ≈ C(n,k) × n² × 常数`。
- 再提 idea：在能理解的范围内多想几个（缓存中间结果、利用对称性、剪枝、调循环顺序）；想不出或超出理解范围不必强求。
- 分清两类：删日志是省 I/O，不是减少计算量。
- AI 用于列候选方向，结论由测量决定。

#### 议题四

- 演示：打 tag → 选热点 → 抽象 → 提 idea → 改一处 → commit → 测 → 填表。

#### 议题五

- 作业：至少两版记录 + 一张可视化图 + 抽象与 idea 说明 + 3 分钟分享。

### 结论

- 优化流程固定为：profiling → 可视化 → 抽象 → 提 idea → 改一处 → 测量 → 记录。
- 每一版都有源码和耗时，可回退、可复现。
