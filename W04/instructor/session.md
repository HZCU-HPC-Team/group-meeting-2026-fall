## 四、讲了什么

### 本次流程顺序

- [x] 学生先汇报
- [x] 讲师先介绍内容

### 议题

1. 回顾 W03 作业：perf 数据是否采到、热点是谁
2. perf 数据可视化：热点条形图、火焰图、前后对比图
3. 从图到假设：按数据选优化方向，AI 辅助的正确用法
4. 版本迭代管理：baseline 标签、一次改动一个 commit、失败用 revert、迭代表
5. 现场演示一轮完整迭代
6. W04 作业布置

### 讨论要点

#### 议题一

- 先查数据覆盖率：没有 perf 数据的同学现场补齐，不进入优化环节。
- 比较各人的采集方式（命令、参数、次数、环境），指出不可比的原因。

#### 议题二

- 热点条形图人人做，数据来自 `perf report --stdio`；火焰图选做，只有 `record -g` 才能做。
- 强调第三张图：前后对比图，横轴版本、纵轴耗时，记录的是决策而不是热闹。
- 读图三问：谁最耗时、在调用栈哪一层、属于计算/访存/分支/I/O 的哪一类。

#### 议题三

- 先写假设再改代码；AI 只做参谋，一次只改一处，说法只当假设。
- 按现象选方向：I/O 与日志、重复计算、访存、分支；编译选项只作对照。
- 让 AI 帮查正确性：浮点顺序、输出格式、边界条件。

#### 议题四

- `git tag v0-baseline`；一次改动一个 commit，message 带数据；失败用 `revert`。
- 维护 `iterations.md`：版本、commit、改动、编译选项、次数、中位数耗时、两档加速比、diff、结论。
- 输入数据与日志不进仓库。

#### 议题五

- 演示一轮：打 tag → 看热点 → 提假设 → 问 AI → 改一处 → commit → `diff` → 测 3 次 → 填表 → 画对比图。
- 若没有收益，现场演示 `revert` 并把失败记入表中。

#### 议题六

- 布置 W04 作业：热点图 + 至少两轮迭代（允许一轮失败）+ 迭代表与对比图 + 3 分钟分享。

### 结论

- 优化从"凭感觉改"转为"看数据 → 写假设 → 改一处 → 测量 → 记录"。
- 每次改动都有版本与数据可追溯，失败也要留档。
- 算法级优化与并行化留到 W05。
