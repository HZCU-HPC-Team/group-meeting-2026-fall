# W04 一页理解：pivot 的重复计算在哪里

## 1. baseline 在算什么

输入是 `dim=2, n=500, k=2`。从 500 个点里选 2 个枢轴，共有

```
C(500, 2) = 124,750 组
```

每组枢轴调用一次 `SumDistance`：

- 重建坐标：`n × k = 1,000` 个“点到枢轴的距离”，每个距离做 `dim` 次 `pow` 和 1 次 `sqrt`；
- 切比雪夫求和：`i, j` 各遍历 `0..n-1`，内层再遍历 `k` 个枢轴，共 `n²k = 500,000` 次比较。

所以总工作量近似为

```
T ≈ C(n,k) × n² × k × c_cheb
  + C(n,k) × n × k × (dim × c_pow + c_sqrt)

n=500, k=2:
  切比雪夫比较  124,750 × 500,000 = 6.2375 × 10^10 次
  距离重建      124,750 × 1,000   = 1.2475 × 10^8 次
```

**重复在哪里**：点 `x` 到某个枢轴 `p` 的距离只由 `x` 和 `p` 决定，与“这一组另一个枢轴是谁”无关，但 baseline 在每一组里都重算；另外 `(i,j)` 和 `(j,i)` 算了两遍，`k=2` 的内层循环也可以用两个指针直接展开。

## 2. AI 提了哪些方案

把 `SumDistance`、`perf report` 和 `perf annotate` 一起发给 AI，得到的候选方案：

| 方案 | 减少的是哪一项 | 预期 | 风险 |
|---|---|---|---|
| 预计算 `n×n` 距离矩阵 | 消掉每组 `pow/sqrt` 和坐标重建 | 去掉约 8.3% 的重建时间，并改善内层访存 | 多 2 MB 内存，可接受 |
| `k=2` 内层特化 | 去掉 `ki` 循环、乘法和重复寻址 | 内层指令更少 | 只对 `k=2` 有效 |
| OpenMP 遍历组合 | 124,750 组之间完全独立 | 接近线性 | 合并要确定性 |
| `i<j` 只算一半再 ×2 | 内层比较直接减半 | 理论 2× | 改变浮点求和顺序，可能影响第 1000 名并列 |
| 多累加器 / AVX 打包 | 打断 `addsd` 串行依赖、一次算多个 double | 理论 2–4× | 同样改变求和顺序，需重新 `diff` |
| 算法改成排序+扫描 | 从 `O(n²)` 降到 `O(n log n)` | 数量级 | 推导复杂，正确性风险最高 |

## 3. 实际做了什么

代码：[src/pivot_opt.c](src/pivot_opt.c)，commit [`9c25975`](https://github.com/HZCU-HPC-Team/group-meeting-2026-fall/commit/9c25975a5d532bfd352a3fe83826d3010df4eebd)。

1. **距离矩阵**：一次性算 `g_dist[p*n + x]`（列主序），之后每组枢轴只查表，不再 `pow/sqrt`；
2. **`k=2` 特化**：直接取 `p0 = g_dist + piv[0]*n`、`p1 = g_dist + piv[1]*n`，内层用两个指针；
3. **OpenMP**：按第一个枢轴做 `schedule(dynamic, 1)`，每个组合写自己的 `sums[rank]` / `combos[rank*k]`，无锁、结果与线程数无关；
4. **确定性选择**：按 `(目标值, 组合 rank)` 排序；值相等时 rank 小的在前，复现参考插入排序的并列顺序；
5. **保留浮点顺序**：仍然按 `i=0..n-1`、`j=0..i-1` 再 `j=i+1..n-1` 累加，对角线贡献是 `+0.0` 所以跳过；没有做 `i<j` 对称翻倍，也没有拆累加器或重排循环。

## 4. 结果

- 1 线程：17,605 ms（3 次中位数），相对 W03 baseline 37,173 ms 为 **2.11×**；
- 20 线程：1,767 ms（3 次中位数），相对 baseline **21.0×**，相对 1 线程 **9.96×**；
- 最终验证跑：1,689 ms，相对 W04 单次 baseline 41,555 ms 为 **24.6×**（与 README 一致）；
- 1 / 2 / 4 / 8 / 20 线程全部 `SAME`，归一化 SHA-256 为 `924858624d0290f1...`；
- 20 线程时间构成：`read 1.6 ms / dist 6.1 ms / enum 1694 ms / select 27.3 ms`，枚举仍占 98%，所以下一步应继续减少枚举内部的计算量。

## 5. 为什么还能逐字节一致

- 预计算用的是和参考完全相同的表达式 `sqrt(Σ pow(diff,2))`，只是把结果复用了；
- 求和顺序保持参考的 `i` 升序、`j` 升序、`k` 升序；跳过对角线只跳过 `+0.0`；
- 排序显式用 rank 处理并列，不依赖 `qsort` 的不稳定行为；
- 并行时每个组合有独立槽位，归并阶段不再改变数值，只按固定规则排序。

因此优化没有改变任何一个组合的目标值，也没有改变第 1000 名附近的并列顺序。下一步若尝试 `i<j` 对称、多个累加器或 AVX，必须先重新跑 `diff`；这些优化会改变浮点求和顺序，不能直接假定结果不变。
