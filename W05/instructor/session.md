## 四、讲了什么

### 本次流程顺序

- [x] 学生先汇报
- [x] 讲师先介绍内容

### 议题

1. 回顾 W04 作业：版本记录、火焰图、优化结果
2. 为什么要并行：主频撞墙、pivot 的可并行结构
3. 阿姆达尔定律：为什么到不了线性
4. 线程、数据竞争、同步开销
5. OpenMP 入门与现场演示
6. W05 作业布置

### 讨论要点

#### 议题一

- 版本记录和基线耗时是并行的前提：没有基线，加速比无从谈起。

#### 议题二

- pivot 的 124,750 组枢轴互不相干，这是可并行的根本原因；
- 先讲"哪部分能切"，再讲"怎么切"。

#### 议题三

- 串行比例 `f` 决定天花板；1% 的串行也能把 20 线程压到 16 倍左右。
- 顺序不能反：先减少计算量，再并行。

#### 议题四

- `sum += x` 拆成读 / 加 / 写三步，两个线程同时做会丢加法，且**不是每次都错**；
- 归约（`reduction`）用来做无锁累加；同步有代价。

#### 议题五

- 三行 OpenMP 起跑；`-fopenmp` 不写，`#pragma` 会被当注释忽略；
- 现场跑 1 / 2 / 4 / 8 线程，每档 `diff` 一致；
- 加速比随线程数增长但效率下降，原因：访存带宽、同步开销、大小核混编。

#### 议题六

- 作业：保留单线程基线 → 加 OpenMP → 测扩展性 → 每档 `diff` → 解释为什么没到线性 → 3 分钟分享。

### 结论

- 并行前先 `diff`，先对再快；
- 加速比要配效率一起看，到不了线性是常态，要能说出原因。
