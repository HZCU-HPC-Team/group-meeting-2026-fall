## 一、为什么有的网站打不开、有的下载很慢？

本节落点：讲清两种成因，引出"我们为什么需要科学上网"。

### 1. 两种现象

- 怎么都打不开：Google 最典型（换浏览器、清缓存、重启路由器都没用）；
- 能用但慢到崩溃：装 WSL、下游戏、pip 装包——爬一晚上，还时不时断。

成因不同，分开讲。

### 2. "打不开" = 被拦截（三招，往往一起上）

- **DNS 污染**：域名解析被塞假地址，连不上——查电话簿、给你假号码；
- **连接阻断**：流量特征被识别，直接掐断——说到一半被挂断；
- **IP 封锁**：目标地址本身被盯上。

结论：Google 这类站点是被"拦"死的，不是玄学。

### 3. "慢 / 断" = 跨境链路拥塞

- 资源在国外，出国要走国际出口——就那么几条，高峰期挤；
- 表现：连得上但极慢、偶尔超时；WSL / Steam / pip / GitHub 都偏这一类（没被拦，就是堵）；
- "你能上、我上不了"很正常——随时间和网络波动，这就是"不稳定"。

### 4. "科学上网"是什么

一句话：不直接连目标网站，先连一台"中转服务器"，让它替你访问。

```
你 ──（加密通道）──► 中转服务器 ──（普通访问）──► 目标网站
```

原理三块：

1. **中转**：出口在中转服务器上，网站看到的来访者是它；
2. **加密通道**：本机到中转之间，数据加密传输；
3. **代收代发**：请求由中转转发，回包沿原路返回。

为什么需要它：Google 查资料、GitHub 看代码、论文文档、开发工具都绕不开；工具五花八门，套路都是"中转 + 通道"。

### 5. 常见形态（点到名字即可）

| 形态 | 通道在哪一层 | 特点 |
|---|---|---|
| HTTP / SOCKS 代理 | 应用层 | 按应用配置，浏览器插件里最常见 |
| VPN | 网络层 | 全局接管，整台设备的流量都走它 |
| SSH 隧道 | 应用层 | 开发者常用，用一台已登录的服务器开条通道 |
| 加密代理协议类软件 | 应用层 | 通道自带伪装和加密，配置各异 |

提示：第三条"SSH 隧道"——等学生连上服务器后正好用得上，后面呼应。

### 6. 三条注意事项

- 来历不明的免费工具不要用（密码、数据可能被中间人拿走）；
- 遵守国家法律法规和学校网络管理规定；
- 绝不在第三方"镜像站"里输入账号密码——镜像只用于下载公开内容，要登录永远去官方网站。

### 7. 省事优先：先试这些

- 换镜像 / 国内源（pip 清华源等）；
- 服务器中转：服务器到国外往往比宿舍顺，让它下载再传回；
- 换时段、换网络重试。

## 二、认识 Git 和 GitHub，加入我们的组织

### 1. Git 和 GitHub 是什么

- **Git**：代码的"时光机"——每次改动都有记录，可回退、可多人合并；
- **GitHub**：建在 Git 之上的代码托管平台，开源项目基本都在上面，组会仓库也在；以后写代码、交作业、找工作都靠它；
- 访问特点：属"慢"的那一类（高峰慢、偶尔断）——前面"省事优先"的镜像和中转就是拿来对付它的。

### 2. 我们的组织

- 组织名 **HZCU-HPC-Team**（团队的"大门牌"）；
- 组会仓库 `group-meeting-2026-fall`：每周目录 + 讲师材料 + 每人一个目录（作业交这里）；之后的项目也会开在组织下。

## 三、我们的服务器

### 1. 基本情况与规矩

- 团队 Linux 服务器（Ubuntu），7×24 在线，每人一个账号；用来跑程序、练 Linux；
- 三条规矩：① 不删改别人的文件；② 不压满 CPU / 内存，重任务先打招呼；③ 密码不外传；
- 卖关子：系统、核数、内存——课上不公布，下周自己探索。

### 2. 账号卡片（四个字段）

| 字段 | 含义 | 理解成 |
|---|---|---|
| IP | 服务器地址 | 门牌地址 |
| 端口 | SSH 服务编号 | 房间号 |
| 用户名 | 你在服务器上的名字 | 工牌 |
| 初始密码 | 首次登录用 | 临时钥匙 |

### 3. 怎么连：两种方式

- 本质都是 SSH：终端命令直连 / VS Code + Remote-SSH 插件（推荐后者：编辑、终端、运行都像本地）；


### 4. 无密码登录（概念）

- 痛点：每次输密码，麻烦且易泄露；
- 做法：SSH 密钥——公钥放服务器、私钥留本地，登录自动验证；
- 配置方法：问 AI（任务 2）。

### 5. 现场上手（时间允许）

- 发卡片，学生自己试连；遇到问题先问 AI（豆包 / Kimi / DeepSeek）。

## 四、布置作业

- 规矩（开场点过题，这里讲细）：技术问题不允许直接问学长操作步骤——**先问 AI → 动手去做 → 做成后把收获留档**；
- 工具：豆包 / Kimi / DeepSeek 网页版均可；
- 一句话点透：把过程留档，是把"AI 教我的"变成"我真正会的"的关键一步；
- 布置时强调：下周带上你的留档材料，分享讲述你对于每个任务的思考、尝试、解决方法。

### 任务 1：连上服务器（必做）

- 你会拿到一张账号卡片（IP、端口、用户名、初始密码）；
- 用 VS Code 的 Remote-SSH 插件连接到服务器；
- 规则：不允许问学长操作步骤，先问 AI。不会问的话，用这个模板起手：

  > 「我有一台 Linux 服务器，IP 是 xxx，端口是 xxx，系统是 Ubuntu。
  > 我想用 VS Code 远程连接它写代码，请一步步教我，我是纯新手。」

### 任务 2：无密码登录（必做）

- 连上服务器后，配置无密码登录（SSH 密钥）；
- 老规矩：步骤不问学长，问 AI。

### 任务 3：自由探索 + 收集命令（必做）

探索问题：

- 这是什么系统？多少核 CPU、多大内存？
- 现在在哪个目录？都有哪些文件？

四类操作，逐条亲手跑通：新建（文件/目录）、查看（内容/目录）、编辑（修改文件内容）、运行（跑一个程序）。

要求：至少 **15 条命令**，整理成一篇《探索笔记》（文件名按仓库规则用英文，建议 `exploration-notes.md`），每条写三样：**命令、作用、实际跑过的例子**。

### 任务 4（选做挑战）

- 尝试把《探索笔记》传到 GitHub 仓库自己的文件夹（`W01/<你的缩写>/`）；
- 组织主页：https://github.com/HZCU-HPC-Team

### 提交方式

- 《探索笔记》放进 `W01/<你的缩写>/`（如 `W01/jy/`）；
- 能自己传上去更好（任务 4 挑战之一）；传不动先存本地，下次组会一起解决；
