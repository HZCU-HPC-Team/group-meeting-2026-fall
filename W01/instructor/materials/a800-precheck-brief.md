# 8×A800 模型部署 · 前置预调研任务书

> 对象：大二同学 ｜ 状态：**机器未到位，纯理论评估**——全部为显存理论估算 + 社区案例佐证，不包含真实延迟 / 吞吐实测；只做可行性预判、上限估算、并发与上下文理论边界。

## 一、背景与目标

- 团队未来将有一台 **8×A800（NVLink，单卡 80GB，总物理显存 640GB）** 服务器；
- 目标：提前调研"这台机器上能部署哪些模型、怎么部署"，挑选**能真正提供生产帮助**的模型；
- 现阶段不上机：机器未到位，先完成**纯理论的前置调研**；机器到位后，按调研结论逐项实测校准。

## 二、交付标准（三项硬性指标）

三项验收重点：① 选了哪个模型、什么**具体版本**、能不能跑；② **理论显存占用 + KV Cache 上下文占用**；③ 针对该硬件的**部署方案 / 落地方式**（同规格成功案例、推理引擎支持）。

### 指标 1：模型清单 + 理论可跑判定

对每个候选模型输出固定字段：

- 模型名称 & **具体版本**（如 `Qwen2-72B-Instruct`，不要只写"Qwen 72B"）；
- 参数量、原生上下文窗口；
- 精度选项：BF16 / FP16 / INT8 / INT4；
- 权重显存理论占用（按统一口径）；
- **KV Cache 估算：给 2–3 个上下文长度档位**（如 4k / 32k / 128k）；
- 并行策略（优先 TP=8，说明理由）；
- 判定：✅ 理论可行 / ⚠️ 勉强可行（资源拉满） / ❌ 无法运行；
- 限制瓶颈标注：显存 / 通信 / 上下文长度。

### 指标 2：开源项目 / 社区案例佐证

对每一个判定【理论可跑】的模型，必须给出：

1. 部署框架：vLLM / TensorRT-LLM / DeepSpeed / HF-Accelerate；
2. **是否已有"8 卡 A800 / NVLink 同规格机器"的成功部署公开案例**（论文、官方文档、GitHub issue、技术博客、官方 demo）；
3. 仓库链接 / 出处；
4. 关键前置条件：量化权重（AWQ / GPTQ）是否有现成开源、依赖版本限制。

> 目的：证明**不是纸上算显存——同硬件已有跑通方案，机器到位后可直接复用**。
> 找不到确凿案例的，标注【待核实】并说明检索范围。

### 指标 3：理论性能预估

> 全部标注【理论值，待上机实测校准】。

1. **单人独占**（batch=1）：最大可支持上下文长度；
2. **多用户并发**：固定输入 2k / 输出 512 token 下，理论最大并发用户数；理论整机吞吐（tokens/s）；
3. **定性预判**：模型中文能力、长文本稳定性；MoE 结构单独说明；
4. **量化损失**：INT4 vs BF16 的质量衰减预估。

## 三、单条调研样例（填写模板）

> 样例：**Qwen2-72B-Instruct**，原生 128k 上下文，稠密 72B。
> （样例仅示意格式与颗粒度；正式结论按统一口径重新核算。）

- **权重**：BF16 = 72 × 2 = 144GB，TP=8 每卡 18GB → ✅ 理论可行；INT4 = 36GB，每卡 4.5GB，余量全留给 KV；
- **社区案例**：vLLM、通义千问官方文档有大量 8×A800 NVLink 成功部署记录；AWQ / GPTQ 现成量化权重齐全；
- **单人独占**：INT4 下理论上可接近 128k 上下文；
- **并发**：输入 2k / 输出 512 token，INT4 下理论可支持数十路（精确数字待核算）；
- **效果**：中文能力强、长文本稳定；INT4 轻微质量衰减，日常业务感知不大。
