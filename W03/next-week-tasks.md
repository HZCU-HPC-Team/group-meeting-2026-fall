### 新生

<!-- 统一流程，任务一致 -->

**规则不变**：先问 AI → 动手去做 → 做成后把收获留档。

**本周特别要求**：跑通赛题时，**不要全部让 Agent 替你敲终端命令**——需要的命令其实不多，希望大家亲手敲一遍、做个简单的实操，并记录下这个过程；等你有了经验，再让 Agent 代劳没关系。

**本周作业：跑通赛题 → 编译优化 → perf 看热点**

- [ ] **1. 跑通赛题**
  - 源码包在组织仓库 `HZCU-HPC-Team/2022_IPCC`（`2022_IPCC/pivot.tar`）；
  - 缺什么先查清：已经有了吗（`which` / `dpkg -l`）？有没有同类工具？有没有更新的版本？查清楚再装；
  - 用自己的方法（查手册 / 问 AI）编译运行，输出与参考结果一致；提交格式以赛题手册 PDF 的要求为准；
  - 单次运行可能要几分钟，用 tmux / nohup 挂着跑；
  - 记录：你亲手敲了哪些命令、每一步在做什么。

- [ ] **2. 说清"最小单位"**
  - 一个程序从源码到跑出结果，最少要经过哪几步（环境 → 源码 → 编译 → 链接 → 运行 → 输出）？你是怎么确认每一步的？

- [ ] **3. 编译优化实验（不改代码）**
  - 只换编译选项：`-O0 / -O1 / -O2 / -O3`（可加 `-march=native`），每种跑 1–3 次；
  - 记录时间、算加速比；
  - 换选项后再 `diff` 一次，确认结果没变。

- [ ] **4. perf 必做（本周重点，也是最难的一块）**
  - 先搞懂 perf 是什么、`stat` / `record` / `report` 各干什么，再动手；
  - `perf stat`：记录 cycles / instructions / cache-misses / branch-misses，判断程序更像计算密集还是访存密集，写出依据（可让 AI 帮解读）；
  - `perf record` + `perf report`：找出占比最大的函数 / 代码段，记下来（大概率是 `SumDistance`）；
  - 记录采集方式：用了什么命令、什么参数、环境是什么、跑了几次；
  - 选做：把热点函数交给 AI，让它解释"为什么慢、有哪些改法"（不要求改代码）。

- [ ] **5. 说明文件 + 分享准备**
  - 说明文件：写清"这周做了什么 + 学到了什么"，PR 到团队仓库的 `W03/<你的缩写>/`；
  - 下次组会**重点分享 perf**：你对 perf 学到 / 了解了什么、数据是怎么采集的（命令 / 参数 / 环境 / 次数）、这些数据有什么用（怎么读、说明了什么）。

**提交**：截止下次组会前；PR 提交到团队仓库的 `W03/<你的缩写>/`。
