# 编译优化实验（不改一行代码，只换编译选项）

> 在两台机器上各做了一遍：**服务器 `hzcu-hpct`（主子）** 和 **本机 Windows（交叉验证）**。
> 结论先说：`-O0 → -O1/-O2` 是唯一的"白捡"（5~9 倍）；之后**再优化基本不动**，`-march=native` 在本题上**没有收益甚至负收益**。

---

## 1. 实验设计

- **变量只有一个**：编译选项。`pivot.c` 一个字节没改，输入文件没动（手册第 4 条：输入不可修改）；
- **档位**：`-O0 / -O1 / -O2 / -O3`，另加 `-O2 -march=native`、`-O3 -march=native`；
- **次数**：服务器每档 **2 次**（共享机，`taskset -c 0` 绑核）；本机每档 **3 次**；
- **判据**：每次换档都重跑并 `diff result.txt refer-2dim-5h.txt`——**结果变了不算数**；
- **计时口径**：以程序打印的 `Using time` 为准（手册第 3 条），外面 `time` 的 wall 只做对照。

规模：`dim=2, n=500, k=2` → 组合数 `C(500,2) = 124750`，每组内层 `n²·k = 500000` 次比较，累计 `6.24×10¹⁰` 次。

## 4. 三处值得写下来的观察

### 4.1 `-O0 → -O1` 就是全部收益的一半以上，而且不同机器/编译器的最优点不一样

| | 服务器 gcc 12.3 | 本机 gcc 16.2 |
|---|---|---|
| 最快档 | **`-O2`（8.25x）** | **`-O1`（9.16x）** |
| `-O1` 相对 O0 | 5.14x | 9.16x |
| `-O2` vs `-O1` | 再快 **1.61 倍** | 反而**慢 13%** |
| `-O3` vs `-O2` | 基本持平（慢 2%） | 快 12% |

同一个程序、同一份源码，**两套编译器给出的"最优档位"是相反的**。这说明"调编译选项"不能照抄结论，必须在自己目标机器上实测——这也是为什么要写脚本跑（见 `scripts/run-o-levels.sh`）而不是拍脑袋。

两者共同点更重要：**从 `-O1` 往上再调，收益都在 ±10% 量级**，相对 `-O0` 的 5~9 倍完全不值一提。

### 4.2 `-march=native` 在本题上完全没用，本机甚至是负收益

- 服务器：`-O2`（60.65 s） vs `-O2 -march=native`（61.94 s）——两者在噪声内持平；
- 本机：`-O3`（33.28 s） vs `-O3 -march=native`（40.31 s）——**慢了 21%**。

为什么？perf 的 `annotate` 给了直接证据：内层循环是 `movsd / maxsd / addsd / andpd` **全是标量指令**，一次处理一个 double；而且 `maxsd` 与 `addsd` 串成两条依赖链。**开 AVX2/AVX-512 也包不起来**（`max` 归约需要横向归约，反而多出 shuffle 与跨域延迟），所以 native 白开，甚至因为调度改变拖长依赖链。

> 一句话：`-march=native` 只对"能向量化"的循环有用，本题的循环瓶颈是**依赖链**而不是**宽度**。要吃到 SIMD，得先改循环结构（重排数据 + 拆累加器 + 手写归约），见 [perf.md](perf.md) 第 6 节。

### 4.3 服务器单核比笔记本慢，但服务器有 128 个核没用上

`-O2` 口径：服务器 60.65 s vs 本机 37.24 s。原因是**单核有效频率**：服务器 `perf stat` 实测 2.596 GHz（共享机 + 全核负载，睿频上不去），本机移动端单核能跑到 4.x GHz。而 baseline 是**单线程**程序，128 核一个都用不上。

**这正是"并行化"在本题上潜力最大的原因**：`C(500,2) = 124750` 组完全独立，OpenMP 铺到 128 线程，理论上能把 60 s 压到秒级（要处理结果合并的确定性）。这是 W04 的主线。

## 5. 计时口径的一个细节（手册没写但代码里能看到）

`pivot.c` 里 `gettimeofday(&start, NULL)` 的位置在 **`fscanf` 读数据之前**：

```c
struct timeval start;
gettimeofday(&start, NULL);      // ← 计时开始
FILE* file = ...;  fscanf(...);  // ← 之后才读数据
```

严格说 `Using time` **包含读文件时间**，与手册"不包括读写文件的时间"的表述有偏差。实测影响：

| | wall (s) | `Using time` (s) | 差 |
|---|---|---|---|
| 服务器 `-O2` | 61.13 | 61.13 | ~0.00 s |
| 本机 `-O2` | 36.92 | 36.83 | 0.10 s |

500 个点的 `fscanf` 在 Linux page cache 下不到 1 ms，可忽略；但这说明**"改计时函数位置"是硬红线**（手册第 3 条明确禁止），要动手只能在循环里做，不能动计时点。

## 6. 复现方式

```bash
# 服务器：一键 6 档 × N 次 + 逐次 diff
bash scripts/run-o-levels.sh              # 默认每档 3 次
REP=2 bash scripts/run-o-levels.sh        # 本次服务器用的就是 2 次

# 单档手动
gcc -O2 -g -o pivot_O2 pivot.c -lm && taskset -c 0 ./pivot_O2 uniformvector-2dim-5h.txt
diff result.txt refer-2dim-5h.txt && echo SAME
```
