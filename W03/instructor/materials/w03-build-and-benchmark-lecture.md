## 二、今天用的赛题：pivot（2022 IPCC）

> 源码包：组织仓库 [`HZCU-HPC-Team/2022_IPCC`](https://github.com/HZCU-HPC-Team/2022_IPCC) 里的 `2022_IPCC/pivot.tar`

**题目在考什么**：从 n 个 dim 维点中选 k 个"枢轴点"，把每个点重新表示为"到各枢轴的距离"，再计算所有点对之间的切比雪夫距离之和；找出这个和最大的 M 组、最小的 M 组枢轴组合并输出。

**源码包内容**：

- `pivot.c`：源代码（纯 C）；
- `uniformvector-2dim-5h.txt`：输入数据（第一行 `dim n k` = `2 500 2`，之后 500 行二维坐标）；
- `refer-2dim-5h.txt`：基准输出（前 1000 组 max、后 1000 组 min 的枢轴下标）。

**怎么跑**：

- 解压：`tar -xf pivot.tar`
- 编译：`gcc -O0 pivot.c -o pivot_O0 -lm`
- 运行：`./pivot_O0 uniformvector-2dim-5h.txt > run.log`（会生成 `result.txt`）
- 校验：`diff result.txt refer-2dim-5h.txt`
- 程序会打印 `Using time : ... ms`，外面也可以再套 `time`
- 提交与输出格式以赛题手册 PDF 的要求为准

**先知道它为什么慢**：算法是"枚举所有 C(n,k) 组枢轴 × 每组重算 n² 个点对"，复杂度 O(C(n,k)·n²)；baseline 单次要跑几分钟，还会打印大量迭代日志（代码注释里写了可以删——W04 我们来改）。

## 三、跑通一个程序的完整链路（本次的"标准动作"）

1. **环境检查**：`which gcc` / `gcc --version`、`lscpu`、`free -h`——先知道自己在什么机器上跑、需要的东西是不是已经有了；
2. **编译**：先 `gcc -O0` 编译；再试 `gcc -O2`——同一份代码，两种速度；
3. **运行**：给输入、看输出；
4. **正确性校验**：和期望输出对比，先对再快；
5. **测量**：`time` 看 wall / CPU 时间；多跑几次取平均；算加速比（`-O2` vs `-O0`）和组合评估速率（组合数 / 时间）；
6. **记录**：环境、编译选项、输入规模、时间、加速比列成表——这就是 ASC 报告的最小雏形。

> **装东西之前先问三件事**：已经有了吗（`which` / `dpkg -l`）？有没有同类工具？有没有更新的版本？查清楚再装——别重复装、别装旧版。

## 四、perf：给程序做"体检"（本周最难，也是重点）

> 先花点时间搞清楚 perf 是什么、能干什么，再动手——不懂 C 也没关系，先建立直觉。

- **三件套**：`perf stat` 是"体检报告"（计数概览）；`perf record` 是"采样记录"；`perf report` 是"看哪里最热"；
- **`perf stat`**：看 cycles / instructions / cache-misses / branch-misses——判断这个程序更像"计算密集"还是"访存密集"，并说出依据；
- **`perf record` + `perf report`**：找出占比最大的函数 / 代码段（这个程序的热点大概率在 `SumDistance`：重建距离 + 两两距离和）；
- 把热点函数丢给 AI 解读"为什么慢、可以怎么改"是加分项，不要求改代码；
- 提示：如果 perf 报权限不足，找讲师。

## 六、布置作业

**本周作业：跑通 → 编译优化 → perf 看热点**

- [ ] **1. 跑通赛题**：用自己的方法（查手册 / 问 AI）编译运行，输出与参考一致；提交格式以赛题手册 PDF 的要求为准；单次可能要几分钟，用 tmux / nohup 挂着跑
- [ ] **2. 说清"最小单位"**：一个程序从源码到跑出结果，最少要经过哪几步（环境 → 源码 → 编译 → 链接 → 运行 → 输出），你是怎么确认每一步的
- [ ] **3. 编译优化实验**：不改代码，只换编译选项 `-O0 / -O1 / -O2 / -O3`（可加 `-march=native`），每种跑 1–3 次记录时间、算加速比；换选项后再 `diff` 一次，确认结果没变
- [ ] **4. perf 必做（本周重点，也是最难的一块）**：
  - 先搞懂 perf 是什么、`stat` / `record` / `report` 各干什么，再动手；
  - `perf stat`：记录 cycles / instructions / cache-misses / branch-misses，判断程序更像计算密集还是访存密集，写出依据（可让 AI 帮解读）；
  - `perf record` + `perf report`：找出占比最大的函数 / 代码段，记下来（大概率是 `SumDistance`）；
  - 记录采集方式：用了什么命令、什么参数、环境是什么、跑了几次；
  - 选做：把热点函数交给 AI，让它解释"为什么慢、有哪些改法"（不要求改代码）。
- [ ] **5. 说明文件 + 分享准备**：
  - 说明文件：写清"这周做了什么 + 学到了什么"，PR 到 `W03/<你的缩写>/`；
